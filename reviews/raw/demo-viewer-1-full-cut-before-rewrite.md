## Part A: answers from the frames only (written before the script)

1. What is this project?
It is a searchable web page, plus a command-line tool and an agent-facing server, that holds short structured write-ups ("entries") of AI-safety experiments that did not work, each taken from a LessWrong or Alignment Forum post (s03-browse-001 header; s05-entry-013 source block). Each entry records what was tested, how it failed, how confident the failure is, and who wrote it and whether anyone has reviewed it, and both people and AI agents can add entries and query them (s01-title-001 subtitle).

2. Who is it for, and what would they use it for?
AI-safety researchers, or AI agents working for them, who are planning an experiment and want to know whether it has been tried and where it went wrong (s01-title-001 caption; s07-ask-002 caption "Say I am planning an experiment"; s08-answer-001 headings "Already tried / Where it went wrong / What to avoid / Worth retrying"). A second audience is people who want to query the entries with SQL (s14-datasette-001 caption).

3. What problem is it trying to solve, and why does that matter?
The problem is stated once, in the opening caption: "AI-safety researchers have no shared place to see what others already tried, and where it failed" (s01-title-001). Why it matters is only implied by the tagline "so the next attempt can be less wrong than the last" (s03-browse-001 header) and "each experiment can be less wrong than the one before it" (s17-close-002). The video never says what a missing shared record costs: nothing on screen or in a caption says work is being repeated, how often, or with what consequence. The second problem, that a thin failure report gets read as "this never works" (s02-idea-001 third bullet), is named as an idea but not shown as a problem until the last scene (s16-finding-005). So the video did not make clear why this matters.

4. How does it work?
Parts seen:
- A web page: a filter panel with counts, a search box, and one card per entry with coloured badges (Unreviewed, Retry welcome, Agent-written, Reviewed by an agent only) and an expandable "All fields" view (s03, s04, s05).
- An entry file: one Markdown file with structured fields such as hypothesis, claim_scope, method, models, limitations (s06-file-001).
- A command-line search that returns a ranked list of entries (s07-ask-001).
- A "local MCP server" with six named tools: fetch_source, get_entry, list_facets, review_entry, search_entries, submit_entry (s07-ask-004; terminal output in s07-ask-001). Only the tool names and two counts are shown.
- An "ask skill" that writes a Markdown answer under the headings Already tried, Where it went wrong, What to avoid, Worth retrying, Not found, with an entry ID on every claim (s08, s09).
- A "contribute skill" that reads a post and submits an entry; submissions go to their own git branch and merge when validation passes (s10 captions; git log in s10-contribute-001).
- A validator (validate.py) that rejected a failure type not in a fixed list and then passed all 15 files (s11-validate-001).
- A GitHub issue form for people, shown as a YAML file, which "a bot" turns into a pull request (s12-human-001).
- A separate review step recorded in git and in a review block inside the entry file (s13-review-001).
- A Datasette check script, and an evals script that reports accuracy for the contribute skill and a pass count for the ask skill (s14, s15).

5. Who or what puts content into it, and who or what reads it?
Putting in: an AI agent, via the "contribute skill" (s10-contribute-002 caption; the entry field in s05-entry-006 shows contributor type agent, a model name, and "contribute-skill v0.1"); and people, via a GitHub issue form that, per the caption, has "not run on GitHub yet" (s12-human-005). The first five cards read "Written by human" next to a yellow note calling them model drafts (s03-browse-001), so who actually wrote those five is unclear to me. Reading: people on the web page; agents through the MCP server, the "ask skill" and the command line (s07, s08); people wanting SQL through Datasette (s14). Reviewing: the only review shown is by an agent, with the reviewer handle HANDLE-TBD (s13-review-001).

6. What did the video actually SHOW working, as opposed to only claiming?
Shown: ticking filter boxes changed the count from 15 to 4 entries (s04-filter-016); typing "steganography" gave 2 of 15 (s04-filter-026); one card expanded to all its fields (s05-entry-004); a command-line search ranked fe-2026-0005 first with score 65 against 6 and 5 (s07-ask-001); two answer files existed with the five headings and entry IDs, including one that says nothing matches (s08-answer-003, s09-notfound-001); the validator rejected a hand-edited file with an error and passed 15 files (s11-validate-001); a git log shows entries 12 to 15 each added on a branch then merged (s10-contribute-001); a review commit and review block exist for entry 7 (s13-review-001); a script printed counts per query (s14-datasette-001); an evals script printed 78% and 6/7 (s15-evals-001).
Claimed but not shown: an agent actually writing an entry or answering a question (only the finished files and a git log are on screen); an agent connecting to the MCP server (only a list of tool names); the issue form running (the caption says it has not); the quote check rejecting a wrong quote (only a pass is shown); the "system stamps the entry as agent-written and unreviewed" claim (s10-contribute-004, with a git log on screen); entries "fixed and resubmitted" after a validation failure (s11-validate-005, with the same terminal on screen); the Datasette interface itself (s14-datasette-001 shows script output, not Datasette).

7. What does it say about how far its content can be trusted, and was that convincing?
It says trust should be visible: each card shows who wrote it, the evidence level (author_report on every card I saw), a "confidence it is a true negative" of low or medium, a claim_scope and limitations field, a source link with a quote the validator found word for word (s02-idea-003; s05-entry-004; s05-entry-006 shows the quote field). The labels are specific and candid. It did not convince me that the content is reliable: 14 of 15 entries are "Unreviewed" (s03-browse-001 counts); the one reviewed entry was reviewed by an agent only, under HANDLE-TBD (s13-review-004); five cards carry a note that they are model drafts not human-verified (s03-browse-010); the word-for-word check is only ever shown passing, against a cache (s11-validate-001, "--quotes cached"); and the accuracy figures are marked PROVISIONAL, with 0% on two fields beside a 78% headline, scored against reference entries the caption says are unverified model drafts (s15-evals-001, s15-evals-005).

8. What are its stated limits or weaknesses?
Stated: the first five entries are model drafts that "I still have to verify" (s03-browse-010); the issue forms "have not run on GitHub yet" (s12-human-005); "five posts with one model vendor is a spot-check, not a benchmark" and the reference entries are unverified (s15-evals-005); evals are labelled PROVISIONAL (s15-evals-001); the wiki holds 15 entries "mostly on sparse autoencoders and interpretability", so a miss "says little about the wider literature" (s09-notfound-001, line 16 of the answer file); most posts do not state enough to fill an entry (s16-finding-003); next steps are a public site, a hosted server, author confirmation and opt-out, and more sources (s17-close-001), which implies it is local only, authors have not confirmed their entries, and it has one source family. Each entry also carries its own claim_scope and limitations (s05-entry-008, s05-entry-013).

9. What is the tone toward the people whose work appears in it?
Stated tone: blameless ("Entries describe experiments, never people", s02-idea-001; s03-browse-001 header). Authors are named in full as source credit on every card. Inside entry text, the limitations field says the author "describes it as a quick effort (a couple of days) and notes limited RL expertise" and "flags the work as a quick effort below their usual standard" (s05-entry-008, s05-entry-013): that is a statement about the author's effort and expertise inside an entry whose banner says it never judges people, even if it is relayed from the author. The phrase "without telling you the idea is dead" (s05-entry-013 caption) is respectful toward the idea. The video shows no sign the named authors have been asked; author confirmation and opt-out appear only as a future step (s17-close-001).

10. What single thing does the video most want you to remember? Was there one?
Not clearly. The line it ends on, and repeats as the small tagline under "Next", is "each experiment can be less wrong than the one before it" (s17-close-002). The body, though, spends most of its time on tooling (filters, a command line, a validator, a Datasette check, evals), and the one result it presents as a discovery, that only 9 of 49 failed-experiment posts state enough to fill an entry (s16-finding-001), arrives in the last minute. What I would walk away with is: a catalogue of failed AI-safety experiments in which every entry shows who wrote it, whether anyone checked, and exactly what was tested. I got that from the three-bullet slide (s02-idea-001), not from the demo scenes.
